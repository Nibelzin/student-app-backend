Resumo

Este trabalho apresenta o desenvolvimento do Student App, uma plataforma web full-stack gamificada para apoio à gestão de estudos de estudantes universitários. A solução é composta por um backend desenvolvido em Java com o framework Spring Boot e um frontend desenvolvido em React com Vite. O sistema oferece funcionalidades de organização acadêmica — controle de disciplinas, períodos, atividades, avaliações e horários — integradas a um sistema de gamificação baseado em pontos de experiência (XP), níveis, moedas virtuais e sequências de estudo (streak). O backend adota a Arquitetura Hexagonal (Ports & Adapters) para garantir o isolamento do domínio de negócio em relação à infraestrutura, expondo uma API REST documentada via Swagger e protegida por autenticação stateless com JSON Web Tokens (JWT). O frontend consome essa API por meio de uma interface de página única (SPA), implementando as principais telas de autenticação, organização acadêmica, sessões de foco e acompanhamento de gamificação. Os resultados demonstram que a abordagem gamificada tem potencial para aumentar o engajamento dos estudantes, promovendo hábitos de estudo mais consistentes.

Palavras-chave: gamificação; gestão de estudos; Spring Boot; React; Vite; arquitetura hexagonal; API REST; Java.

Abstract

This work presents the development of Student App, a gamified full-stack web platform for academic management support aimed at university students. The solution consists of a backend developed in Java with the Spring Boot framework and a frontend developed in React with Vite. The system provides academic organization features — subject and period management, activities, assessments, and class schedules — integrated with a gamification system based on experience points (XP), levels, virtual coins, and study streaks. The backend adopts the Hexagonal Architecture (Ports & Adapters) pattern to ensure domain isolation from infrastructure concerns, exposing a REST API documented via Swagger and secured with stateless JWT authentication. The frontend consumes this API through a Single Page Application (SPA) interface, implementing the main screens for authentication, academic organization, focus sessions, and gamification tracking. Results indicate that the gamified approach has the potential to increase student engagement, promoting more consistent study habits.

Keywords: gamification; study management; Spring Boot; React; Vite; hexagonal architecture; REST API; Java.

1 Introdução

O ambiente universitário impõe aos estudantes a necessidade de gerenciar, simultaneamente, múltiplas disciplinas, avaliações, atividades extracurriculares e compromissos pessoais. Essa sobrecarga cognitiva frequentemente resulta em baixa produtividade, procrastinação e abandono dos estudos. Ferramentas digitais de organização pessoal têm sido amplamente adotadas como alternativa para mitigar esses problemas, mas muitas carecem de mecanismos que promovam o engajamento contínuo do usuário.

A gamificação — aplicação de elementos e mecânicas de jogos em contextos não lúdicos — surge como uma abordagem promissora para aumentar a motivação e a persistência em plataformas educacionais. Ao incorporar sistemas de pontuação, níveis e recompensas ao processo de organização acadêmica, é possível criar um ciclo de feedback positivo que incentiva o estudante a manter hábitos de estudo regulares.

Neste contexto, o presente trabalho descreve o desenvolvimento do Student App: uma aplicação web full-stack composta por um backend em Java/Spring Boot e um frontend em React/Vite, com o objetivo de oferecer uma plataforma integrada de gestão acadêmica gamificada.

2 Referencial Teórico

2.1 Gamificação

O termo gamificação foi popularizado por Deterding et al. (2011) e designa o uso de elementos de design de jogos em contextos não lúdicos, com o objetivo de aumentar o engajamento e a motivação dos usuários.

2.1.1 Elementos de Gamificação

  • Pontos de Experiência (XP): progresso do usuário ao concluir atividades. O acúmulo de XP determina o nível atual;
  • Níveis: estrutura de progressão com limiar crescente — 100 × nível_atual de XP para avançar;
  • Moedas Virtuais: recompensas adicionais para benefícios dentro da plataforma;
  • Streak: contador de dias consecutivos de estudo, incentivando a consistência.

2.3 Arquitetura de Software

2.3.1 Arquitetura Hexagonal (Ports & Adapters)

A Arquitetura Hexagonal, proposta por Cockburn (2005), isola o núcleo da aplicação (domínio de negócio) de agentes externos. É composta por três elementos:

  • Núcleo (Domínio): regras de negócio e entidades, sem dependência de frameworks;
  • Portas de Entrada (Input Ports): interfaces que expõem os casos de uso;
  • Portas de Saída (Output Ports): interfaces para recursos externos (banco de dados, e-mail, armazenamento).

2.3.2 API REST

O estilo arquitetural REST, descrito por Fielding (2000), define restrições para sistemas distribuídos: comunicação stateless, interface uniforme e uso semântico dos verbos HTTP (GET, POST, PUT, DELETE). No Student App, a API REST é o contrato de comunicação entre frontend e backend.

2.4 Desenvolvimento Frontend com React

2.4.1 Single Page Application (SPA)

Uma SPA é uma aplicação web que carrega um único documento HTML e atualiza o conteúdo dinamicamente via JavaScript, sem recarregar a página. Essa abordagem proporciona uma experiência de navegação mais fluida e próxima de aplicações nativas, sendo amplamente adotada em sistemas modernos.

2.4.2 React e Componentização

React é uma biblioteca JavaScript para construção de interfaces de usuário baseada no conceito de componentes — unidades reutilizáveis e independentes que encapsulam estrutura, comportamento e estilo. Seu modelo de renderização utiliza um DOM virtual (Virtual DOM) para aplicar apenas as mudanças necessárias no DOM real, garantindo eficiência de atualização.

⚠️ Aprofunde com referência bibliográfica sobre React. Mencione hooks (useState, useEffect, useContext) e o modelo de fluxo unidirecional de dados.

2.4.3 Vite como Bundler

Vite é uma ferramenta de build moderna que utiliza módulos ES nativos durante o desenvolvimento, eliminando a necessidade de empacotar o código a cada alteração. Isso resulta em um servidor de desenvolvimento com tempo de inicialização significativamente menor em comparação a ferramentas anteriores como Webpack.

2.5 Comunicação Cliente-Servidor

A comunicação entre o frontend React e o backend Spring Boot é realizada via requisições HTTP assíncronas à API REST. O token JWT obtido no login é armazenado no cliente e enviado no cabeçalho Authorization: Bearer <token> a cada requisição autenticada.

3.4 Estratégia de Testes

A estratégia de testes concentra-se na camada de domínio do backend, em conformidade com os princípios da Arquitetura Hexagonal. Os testes foram implementados com JUnit 5 e Mockito, cobrindo:

  • Testes de modelos de domínio: verificação das regras de negócio encapsuladas nas entidades, como User.awardXp();
  • Testes de serviços: verificação dos ServiceImpl com repositórios mockados;
  • Testes de controladores: verificação dos endpoints REST com @WebMvcTest.

No frontend, a validação foi realizada de forma manual, por meio da navegação nas telas e verificação da integração com a API durante o desenvolvimento. Testes automatizados de interface estão previstos como trabalho futuro.

4.2.3 Sistema de Gamificação

O limiar de XP para subir de nível é definido por: XPnecessário = 100 × nível_atual. O método User.awardXp() preserva XP excedente ao subir de nível e retorna true quando uma subida ocorre, disparando uma notificação LEVEL_UP. XP é concedido em dois eventos: conclusão de Activity (50 XP, apenas na primeira vez) e encerramento de FocusSession (proporcional à duração).

4.2.4 Segurança e Autenticação

A autenticação é stateless via JWT. No login, o JwtService gera um token assinado que o cliente armazena e envia no cabeçalho Authorization: Bearer <token>. O filtro JwtAuthFilter valida o token a cada requisição. O controle de acesso usa roles (USER e ADMIN).

4.2.5 Camada de Persistência

5.3 Avaliação da Arquitetura

A separação em frontend e backend independentes trouxe benefícios claros: as duas camadas evoluem em ritmos distintos sem interferência mútua, e a API REST pode ser consumida futuramente por outros clientes (aplicativo móvel, por exemplo). No backend, a Arquitetura Hexagonal garantiu testabilidade isolada da lógica de negócio e substituição desacoplada de componentes de infraestrutura.

6 Conclusão

Este trabalho apresentou o desenvolvimento do Student App, uma plataforma web full-stack gamificada para gestão de estudos universitários. A solução integra um backend robusto em Java/Spring Boot, construído sobre a Arquitetura Hexagonal, a um frontend moderno em React/Vite, conectados por uma API REST protegida com JWT.

Os objetivos específicos foram alcançados no backend de forma completa, incluindo a modelagem do domínio com 18 entidades, o sistema de gamificação com progressão de XP e níveis, o módulo de sessões de foco, a API REST documentada e o sistema de notificações com deduplicação. O frontend encontra-se em desenvolvimento, com as telas de autenticação e as principais funcionalidades acadêmicas em fase de implementação e integração.

6.1 Limitações

⚠️ Descreva as limitações atuais: frontend ainda em desenvolvimento, ausência de testes automatizados de interface, sem avaliação formal com usuários reais, ambiente de produção não configurado etc.

6.2 Trabalhos Futuros

  • Conclusão e polimento do frontend: finalização de todas as telas e refinamento da experiência do usuário;
  • Avaliação com usuários reais: estudo de usabilidade e eficácia da gamificação com estudantes universitários;
  • Testes automatizados de interface: implementação de testes com Cypress ou Playwright;
  • Conquistas (badges): expansão da gamificação com conquistas desbloqueáveis por marcos específicos;
  • Ranking e elementos sociais: tabelas de classificação e funcionalidades colaborativas;
  • Aplicativo móvel: clientes iOS/Android consumindo a mesma API REST, com notificações push;
  • Deploy em produção: configuração de ambiente de produção com CI/CD automatizado.
