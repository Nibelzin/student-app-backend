Resumo

Este trabalho apresenta o desenvolvimento de uma plataforma web gamificada para apoio à gestão de estudos de estudantes universitários. A solução, denominada Student App, oferece funcionalidades de organização acadêmica — controle de disciplinas, períodos, atividades, avaliações e horários — integradas a um sistema de gamificação baseado em pontos de experiência (XP), níveis, moedas virtuais e sequências de estudo (streak). O backend da aplicação foi desenvolvido em Java com o framework Spring Boot, adotando a Arquitetura Hexagonal (Ports & Adapters) para garantir isolamento do domínio de negócio em relação à infraestrutura. O sistema expõe uma API REST documentada via Swagger e utiliza autenticação stateless com JSON Web Tokens (JWT). Os resultados demonstram que a abordagem gamificada tem potencial para aumentar o engajamento dos estudantes com a plataforma, promovendo hábitos de estudo mais consistentes.

Palavras-chave: gamificação; gestão de estudos; Spring Boot; arquitetura hexagonal; API REST; Java.

Abstract

This work presents the development of a gamified web platform for academic management support aimed at university students. The solution, named Student App, provides academic organization features — subject and period management, activities, assessments, and class schedules — integrated with a gamification system based on experience points (XP), levels, virtual coins, and study streaks. The application backend was developed in Java using the Spring Boot framework, adopting the Hexagonal Architecture (Ports & Adapters) pattern to ensure domain isolation from infrastructure concerns. The system exposes a REST API documented via Swagger and uses stateless authentication with JSON Web Tokens (JWT). Results indicate that the gamified approach has the potential to increase student engagement with the platform, promoting more consistent study habits.

Keywords: gamification; study management; Spring Boot; hexagonal architecture; REST API; Java.

1 Introdução

O ambiente universitário impõe aos estudantes a necessidade de gerenciar, simultaneamente, múltiplas disciplinas, avaliações, atividades extracurriculares e compromissos pessoais. Essa sobrecarga cognitiva frequentemente resulta em baixa produtividade, procrastinação e abandono dos estudos. Ferramentas digitais de organização pessoal têm sido amplamente adotadas como alternativa para mitigar esses problemas, mas muitas carecem de mecanismos que promovam o engajamento contínuo do usuário.

A gamificação — aplicação de elementos e mecânicas de jogos em contextos não lúdicos — surge como uma abordagem promissora para aumentar a motivação e a persistência em plataformas educacionais. Ao incorporar sistemas de pontuação, níveis e recompensas ao processo de organização acadêmica, é possível criar um ciclo de feedback positivo que incentiva o estudante a manter hábitos de estudo regulares.

2 Referencial Teórico

2.1 Gamificação

O termo gamificação (gamification) foi popularizado por Deterding et al. (2011) e designa o uso de elementos de design de jogos em contextos que não são jogos, com o objetivo de aumentar o engajamento, a motivação e o comportamento dos usuários.

2.1.1 Elementos de Gamificação

Os principais elementos gamificados utilizados neste trabalho são:

  • Pontos de Experiência (XP): representam o progresso do usuário ao completar atividades e sessões de estudo. O acúmulo de XP determina o nível atual do estudante;
  • Níveis: estrutura de progressão que requer quantidades crescentes de XP. O limiar por nível é calculado como 100 × nível_atual;
  • Moedas Virtuais: recompensas adicionais que podem ser utilizadas para obter benefícios dentro da plataforma;
  • Sequência de Estudo (Streak): contador de dias consecutivos em que o usuário realiza atividades na plataforma.

2.3 Arquitetura de Software

2.3.1 Arquitetura Hexagonal (Ports & Adapters)

A Arquitetura Hexagonal, proposta por Cockburn (2005), tem como objetivo central isolar o núcleo da aplicação (domínio de negócio) de agentes externos, como interfaces de usuário, bancos de dados e sistemas de mensageria. O modelo é composto por três camadas:

  • Núcleo (Domínio): contém as regras de negócio, entidades e casos de uso, sem qualquer dependência de frameworks ou tecnologias externas;
  • Portas de Entrada (Input Ports): interfaces que definem os casos de uso que o domínio expõe para o mundo externo;
  • Portas de Saída (Output Ports): interfaces que definem os recursos externos que o domínio necessita.

3.4 Estratégia de Testes

A estratégia de testes concentra-se na camada de domínio, em conformidade com os princípios da Arquitetura Hexagonal, que recomenda que o núcleo da aplicação seja testável de forma isolada, sem dependência de frameworks ou infraestrutura.

Os testes foram implementados com JUnit 5 e Mockito, cobrindo:

  • Testes de modelos de domínio: verificação das regras de negócio encapsuladas nos métodos das entidades, como User.awardXp() e os construtores via factory methods;
  • Testes de serviços: verificação do comportamento dos ServiceImpl com repositórios mockados;
  • Testes de controladores: verificação dos endpoints REST com @WebMvcTest.

4.4 Sistema de Gamificação

4.4.1 Progressão de XP e Níveis

O limiar de XP necessário para avançar de nível é calculado como:

XPnecessário = 100 × nível_atual

O método User.awardXp(int amount) implementa a concessão de XP com preservação de XP excedente (overflow) ao subir de nível: 

public boolean awardXp(int amount) {
    this.currentXp += amount;
    int threshold = 100 * this.currentLevel;
    if (this.currentXp >= threshold) {
        this.currentXp -= threshold;   // preserva overflow
        this.currentLevel++;
        touch();
        return true;   // indica subida de nível
    }
    touch();
    return false;
}
Código 3 — Método awardXp da entidade User

4.4.2 Eventos de Gamificação

A concessão de XP ocorre em três eventos principais:

  • Conclusão de Atividade: ao marcar uma Activity como concluída pela primeira vez, o usuário recebe 50 XP;
  • Sessão de Foco: ao encerrar uma FocusSession, o XP é proporcional à duração da sessão (durationSeconds);
  • Subida de Nível: quando awardXp() retorna true, uma notificação LEVEL_UP é criada.

4.4.3 Controle de Faltas e Notificações

O AbsenceLogServiceImpl monitora o percentual de faltas. Quando o limite de 75% é atingido, uma notificação ABSENCE_LIMIT é criada, com deduplicação via NotificationRepositoryPort.existsUnreadByUserIdAndTypeAndReferenceId().

4.5 Segurança

4.5.1 Autenticação JWT

  1. O cliente realiza login em POST /auth/login com e-mail e senha;
  2. O JwtService gera um token assinado com a chave secreta configurada;
  3. Nas requisições seguintes, o cliente inclui o token no cabeçalho Authorization: Bearer <token>;
  4. O filtro JwtAuthFilter valida o token a cada requisição.

4.5.2 Autorização

  • USER: acesso aos próprios recursos acadêmicos e de gamificação;
  • ADMIN: acesso às rotas /admin/** para operações administrativas.

5.3 Avaliação da Arquitetura

A adoção da Arquitetura Hexagonal trouxe benefícios observáveis:

  • Testabilidade: serviços de domínio testados sem instanciar beans do Spring;
  • Substituição de adapters: implementação de armazenamento trocável sem alterar o domínio;
  • Legibilidade: separação clara de responsabilidades facilita manutenção.

Como contrapartida, a arquitetura exige a criação de um número maior de classes (duas camadas de mapeamento, interfaces de porta, adaptadores), aumentando o boilerplate inicial.

6 Conclusão

Este trabalho apresentou o desenvolvimento do Student App, uma plataforma web gamificada para apoio à gestão de estudos universitários. A solução integra ferramentas de organização acadêmica com mecânicas de engajamento baseadas em gamificação, como pontos de experiência, níveis progressivos, moedas virtuais e sequências de estudo.

O backend foi desenvolvido em Java 17 com Spring Boot 3.5.6, adotando a Arquitetura Hexagonal. Essa escolha demonstrou-se adequada, garantindo isolamento das regras de negócio da infraestrutura, facilitando os testes unitários e tornando os componentes de infraestrutura substituíveis de forma independente.

Os objetivos específicos foram alcançados:

  • O módulo de organização acadêmica foi implementado com todos os fluxos de CRUD;
  • O sistema de gamificação com XP, níveis, moedas e streak foi integrado;
  • As sessões de foco com recompensa de XP proporcional foram implementadas;
  • A Arquitetura Hexagonal foi aplicada de forma consistente;
  • A API REST foi documentada via Swagger UI e protegida com JWT;
  • O sistema de notificações com deduplicação foi implementado.

  • Ranking e elementos sociais: tabelas de classificação e funcionalidades colaborativas;
  • Análise de desempenho: relatórios sobre histórico de estudos e evolução das notas;
  • Aplicativo móvel: clientes iOS/Android com notificações push;
  • Testes de integração e carga: ampliação da suíte de testes.
